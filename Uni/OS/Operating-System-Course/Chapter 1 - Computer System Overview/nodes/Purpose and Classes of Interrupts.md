# Purpose and Classes of Interrupts
**Problem:** Most I/O devices are slower than the processor, so a processor that pauses to wait for a device wastes cycles.
**Mechanism:** Interrupts are a mechanism by which other modules may interrupt the normal sequencing of the processor, provided to improve processor utilization. Table 1.1 groups causes into four classes: Program (arithmetic overflow, division by zero, illegal instruction, out-of-bounds memory reference), Timer (periodic OS functions), I/O (normal completion or error signaled by an I/O controller), and Hardware failure (e.g. power failure, memory parity error).

## Key points
- [x] Interrupts let other modules interrupt the processor's normal instruction sequencing, improving processor utilization since most I/O devices are slower than the processor. (p.19)
- [ ] Without interrupts, the processor would pause and wait for a device — a wasteful use of the processor. (p.19)
- [ ] Program interrupts are generated by conditions from instruction execution: arithmetic overflow, division by zero, illegal instruction, or out-of-bounds memory reference. (p.20)
- [ ] Timer interrupts are generated by an internal processor timer, letting the OS perform functions on a regular basis. (p.20)
- [ ] I/O interrupts are generated by an I/O controller to signal normal completion or an error condition. (p.20)
- [ ] Hardware-failure interrupts are generated by failures such as power loss or memory parity errors. (p.20)
